## 1. 为什么这份材料重要

v1/v2 讲腾讯 / 阿里 / DeepSeek，靠的是百科词条、媒体报道与企业内容转述（B/C 级），因此在手册里只能当「别人怎么做」的描述，不能当硬依据。本轮找到信通院 2026 年《驾驭工程：赋能智能原生软件工程研究报告》，第一次有了**系统汇总国内头部实践的官方发布物**。

更关键的是交叉印证：Thoughtworks Technology Radar Vol 34（2026-04）把 `harness engineering` 列为新浮现的正式术语，信通院同年报告把「驾驭工程 / Harness Engineering」作为报告主题——**两个独立来源、同一年、指向同一个概念**：行业关注点已从「模型/工具」转向「包住 Agent 的基础设施、约束与反馈回路」。这是本轮少见的**增强信心**而非削弱信心的发现。

## 3. 报告指出的三大产业瓶颈（最值得抄进准则的部分）

1. **工程化思维缺位 + 存量系统历史包袱**
   多数团队仍偏重大模型算法精度优化，忽视驾驭工程所需的**稳定性、兼容性、部署成本**等综合工程指标；存量系统参数冗余、环境适配差、容错不足，导致全链路管控与软硬件协同迭代难落地，技术原型转产业方案试错成本高。
   报告引 Gartner《2025 企业 AI 架构成熟度报告》：**AI 落地失败的根源并非单一技术缺陷，而是「资源供给、数据治理、系统协同、安全合规」构成的系统性架构失衡**。
   → 对应 DORA「amplifier」、The Pragmatic Engineer「AI 是放大器不是修复器」、手册 4.6 成熟度阶梯。

2. **行业工程体系高度碎片化**
   国内商用/开源大模型 >200 款，主流厂商采用私有 API 协议，接口参数、请求格式、流式响应、错误码无统一标准。2026 年行业调研：**>68% 开发者需为不同模型单独写适配代码，35% 的 AI 项目迭代耗时消耗在接口调试、格式兼容、异常适配**。
   → 这是「工具/协议碎片化」的量化依据，支持 E3 政策里必须管**工具一致性**，也支持 G2 私域回归集（换模型就要复测适配层）。

3. **全生命周期闭环管控普遍缺失**
   传统静态线性开发模式与驾驭工程动态进化逻辑相悖；行业普遍「重单点功能、轻体系治理」「重短期交付、长效运维不足」。
   → 直接支撑 L 章（时效性与复审）与 I3（下游成本指标）。

## 4. 报告对「驾驭工程」的定位

报告把国内路径概括为「本土化适配、自主可控、行业合规」：阿里云、腾讯、字节、DeepSeek 等头部企业搭建自研驾驭中间层，针对信创环境优化**权限管控、隐私计算、国产数据库适配**，侧重**共享记忆、流程柔性配置、多模型兼容**。供给侧形成「平台自研 + 开源并行」格局；应用从互联网头部向金融、制造、政务纵深拓展。

> 与手册的关系：这是「协议与权限」（H 章）、「上下文与记忆」（B5/I4）、「最小权限」（H2）在国内工程语境下的对应表述，说明这些准则不是西方材料的照搬，国内头部实践也在收敛到同样的结构性问题上。
