## 2. 商业机构的纵向分析（B 级，取趋势不取精确值）

**GitClear**：2025 年 AI Copilot Code Quality 研究分析 2021–2025 年间约 2.11 亿行代码变更（私有仓库 + 大型开源项目）。多个版本报告的具体年份与百分比略有差异，但趋势一致：

- 重构 / 移动（moved）代码占比**显著下降**（有 24.1%→9.5%、25%→<10% 两种口径）。
- 复制粘贴 / 重复代码块占比**显著上升**（8.3%→12.3%、8%→18% 两种口径）。
- 短期 churn（提交后短期被改写的行）上升。
- 其 2026 年更新（C 级，未回查）称重构 −70%、遗留维护 −74%、块级重复 +81%。

> **口径警示**：不同版本报告对比基线不同，手册只写「重构下降、重复与返工上升」这一方向，不写死数字。

**CodeRabbit**（C 级，未回查）：约 470 个开源 PR 的分析中，AI 参与 PR 平均约 10.83 个问题 vs 纯人工 6.45 个（约 1.7 倍）。

## 3. 2026 年遥测汇总（C 级，仅作趋势，**未逐条回查，不进手册正文作硬结论**）

综合检索返回的二手汇总中包含以下说法，本轮未独立核实，登记备查：

| 来源 | 说法 |
|---|---|
| Faros AI（称 22,000 开发者遥测） | PR 评审中位时长 +441%；31% PR 无评审即合并；PR 体积 +51.3%；人均 bug +54%；每 PR 生产事故概率 +242.7% |
| LinearB（称 810 万 PR） | 智能体 PR 等待评审时间是人类的 5.3 倍；30 天合并率 32.7% vs 人工 84.5%；重度 AI 团队合并 PR +98% 但评审时间 +91%，净组织生产力提升约 10% |
| Code Ninety | 单 PR 前置时间 −32.4%，但缺陷注入率 +50%、安全告警 +61.1%、评审时间 +41.5%；具备自动化准入与 TDD 的组织消除 80%+ 缺陷注入惩罚 |
| McKinsey / Jellyfish / Sonar / JetBrains / Harness / DX | 例行编码任务时间 −46% 但高复杂度工作 <10%；token 用量最高者吞吐量 2x 而成本 10x；61% 认为 AI 常产出「看起来对但不可靠」的代码；89% 负责人报告提效但 81% 报告评审时间增加；「质量悖论」可维护性 +3.8% 而变更信心 −6.1% |

**统一解读**：无论这些数字最终能否逐一核实，它们与 A 级的 DORA / Stack Overflow / GitClear 指向同一现象——**加速生成、下游承压**。手册 C4 因此只依赖 A 级证据立论，C 级材料仅作旁证与后续补查线索。

## 4. 「验证税」的完整论证

```
AI 提高生成速度
   ↓
单位时间产出更多、更大的变更（DORA 2024 的小批量解释）
   ↓
评审队列变长、评审停留时长上升、无评审合并增多
   ↓
缺陷逃逸、变更失败、返工（churn）上升
   ↓
生成环节省下的时间被审计与修复吃掉 → 净收益低于感知
```

**对应的止血机制（多源指向同一处）**：小批量工作 + 自动化准入检查 + TDD + 快速高质量反馈闭环 + 把 AI 同时投到评审与测试。这正是手册 B4、C4、D1、E1 的共同落点。

## 5. DORA 2025 七项 AI 能力模型（官方博客列出方向，逐项定义待补）

1. 清晰且已沟通的 AI 立场 / 政策
2. 健康、可被 AI 访问的数据生态
3. AI 可访问的内部代码与知识仓库（结构可被智能体导航）
4. 强版本控制实践
5. 小批量工作
6. 以用户为中心
7. 高质量内部平台

> 与手册的映射：1→E3，2/3→A1/B5，4→A2/D1，5→B4，6→E1，7→C4/B6。
> 官方博客另给出「90% 组织已采用至少一个内部平台，但决定收益的是平台**质量**而非存在与否」的判断。

## 6. DORA 2024 的三条组织建议（A 级，直接可抄）

1. 让 AI 采纳策略以「赋能员工、减少苦活」为导向。
2. 建立清晰的使用指引，公开沟通 AI 影响，处理流程顾虑。
3. 给开发者**工作时间内的**探索与试验时间，通过动手建立信任。

另有 dora.dev 报告页给出与政策/学习时间/沟通相关的采纳率差异数据（A 级页面，具体倍数未在本轮回查中逐条核对，见存疑清单）。
