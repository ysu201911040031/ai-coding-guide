## 1 · 三条硬筛（缺一不收）

| # | 判据 | 不合格怎么办 |
|---|---|---|
| 1 | **许可明确**：CC0 / MIT / Apache-2.0 / BSD；GPL 仅在同样开源时可用 | 无 LICENSE 或「保留所有权利」→ 只登记链接，不下载 |
| 2 | **近 12 个月有实质提交**；停更的必须标注 | 停更 → 只当论文/历史索引用，不进快照 |
| 3 | **能一句话说清解决什么问题** | 说不清 → 不收；纯合集默认不合格 |

**star 只作发现信号，不作判据**：本表不写 star 数、不按 star 排序。star 是易变事实，且同一仓库在二手站可能差 3 倍以上。

## 4 · 快照怎么做

```
99-本机专用/提示词快照/<owner>-<repo>-<commit7>/
├── LICENSE        # 原件，不改
├── 来源.md        # URL / commit SHA / 取回日 / 许可 / 用途
└── <需要的文件>    # 只取用到的，不整仓
```

1. 打开仓库：先看 LICENSE，再看最近一次实质提交。
2. 记录 commit SHA（`git rev-parse HEAD` 或页面上的短哈希）。
3. **只复制需要的文件**，不整仓 clone。
4. 写 `来源.md`，并在本表「快照」列填目录名。
5. 使用一次就更新一次次数/时间（D9，只记两端）。

**禁止**：把整仓当上下文喂给模型（违反 M1）；把原文复制进公开仓库（许可不兼容）；快照里放凭据。

## 5 · 检索顺序（止损 20 分钟）

1. 项目内：`prompts.md`、`.ai/` 任务卡、`AGENTS.md`。
2. 本表 §2 白名单 → 本地快照。
3. 白名单仓库的官方页面（按文件取，不按仓库取）。
4. GitHub 搜索——**只作发现**，结果必须回一手核（许可 + 活跃度 + 用途）。
5. 20 分钟无果 → 自己写，记一句「已搜无果」（D8）。

## 6 · 为什么不做自动搜索

- GitHub 代码搜索需要 token；按本仓库规则，AI 不持有凭据。
- 未鉴权的仓库搜索限流低，撑不住「每次开发前自动搜」。
- 提示词合集类仓库质量参差，自动下载会把噪声直接带进上下文。

结论：**人工按需检索 + 快照建档**，不做爬虫。
