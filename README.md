# AI 辅助软件开发 · 准则手册与证据卷

> 一套**带保质期**的 AI 编码协作准则：74 条准则 + 五层审阅批注 + 可回查的来源索引 + 一个多平台配置包。
> 语言：简体中文 ｜ 手册版本 v3.6

**这不是一组已站稳的规范，而是一组带保质期的假设。** AI 辅助开发的新范式还没经历过足够长的生产与变更周期。
所以每条准则都标了**来源类型**（行业/开源/研究/偏好）、**优先级**（P0–P3）、**可信等级**（A/B/C），
并配了「什么时候会失效」与「怎么把它推翻」。请连同 L 章（时效性）与 N 章（自身可信度审计）一起读。

## 最小可行集：从 5 条开始，不要一次上 74 条

手册 4.5 节给了最小集。核心就这几条：

1. **自检先请示** —— 编译、测试、lint、跑程序，先说「跑什么·验什么·影响面·耗时」再执行。
2. **破坏性动作人工批** —— 删除、force push、部署、生产变更，先列清单 + 风险 + 回滚方式。
3. **做减法必须留原稿** —— 精简版一律新建文件，绝不覆盖；封存记 SHA-256。
4. **验收判据必须与生成判据不同源** —— 自己出题自己答等于没验。
5. **运行期真相由人给** —— 静态代码不含运行期事实，AI 会给出「看起来合理」的错误推断。

## 三条方法纪律（比结论更值得抄）

**① 凡数字必查原始出处。** 同一指标在不同来源口径不一致时，取趋势不取精确值，并把冲突记进
[`存疑与待核实.md`](06-来源索引/存疑与待核实.md)。引用量化结论必须同时写出：**样本 / 口径 / 年份 / 是否相关性**。

**② 验收判据必须与生成判据不同源。** 这条是踩出来的：用脱敏脚本自己的模式表去验脱敏结果，
必然报「0 残留」——换一套独立正则立刻查出上百处。**自己出题自己答等于没验。**

**③ 易变的事实进检查，不进规则。** 版本号、分支名、star 数、行数一律实测，不写死在文档里。
实测教训：二手 star 追踪站对同一个仓库给出的数字差 3 倍以上。

## 关于可信度（请先读这段再用）

| 项 | 内容 |
|---|---|
| 生成 | AI 多轮检索与撰写 |
| 审阅 | 多层批注：GLM 21 条 → 第三层 12 条 → 第四轮 15 条，**逐层裁决、保留分歧** |
| **人工确认** | **无**——本仓库内容未经人工逐条核实 |
| 未核实项 | 见 [`06-来源索引/存疑与待核实.md`](06-来源索引/存疑与待核实.md) |
| 已知内部硬伤 | 审阅批注 R-03：用自报数据量化「验证税」，与 E2「自报不作决策依据」自相矛盾 |

**A/B/C 可信等级**：

- **A** 一手可回查（论文原文、官方规范、官方博客、官方仓库）→ 可作结论依据
- **B** 机构自报或大样本调查（方法公开，但结论为相关性或自报）→ 可引用，必须标口径与样本
- **C** 二手转述、厂商案例、技术媒体 → **只用于理解趋势，不得作为决策依据**

## 审阅批注怎么读

手册正文内嵌三种批注标记，**成段插入、可整体移除而不伤结构**：

- 🔖 第二层（GLM，R-01…R-21）
- 🔍 第三层（T-01…T-12，完整通读后重做，含对第二层 21 条的完整裁决）
- 🧭 第四轮（Q-01…Q-15，只插 5 处会改变行为的）

每层都声明了立场与局限。**最重要的一条自我批评**：第二层审阅者与原产物同源，
那次不是独立交叉审阅——建议由异源模型或人类做第三遍。

## 配置包用法

```bash
cd 07-一键落地
bash setup.sh --list                    # ① 看会装到哪（默认 dry-run，不写任何文件）
bash setup.sh --apply --proj=/你的/仓库  # ② 装（覆盖前自动备份，生成回滚脚本）
bash setup.sh --paste                   # ③ 给网页版 AI 生成可粘贴文本
```

一个源头 `core/00-协作铁律.md` + 项目约定 `project.local.md` → 各平台认的格式。
换项目只改 `project.local.md`，脚本不用动。
