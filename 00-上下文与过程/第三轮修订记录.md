## 1. 本轮定位

前两轮分别是「收集证据 → 立规矩」（v1）与「补盲点 → 把三处结论改弱」（v2）。v3 做的是：

1. **证伪**：对已立的 P0 逐条找反例与失效条件。
2. **裁决**：把互相矛盾的权威结论摆在一起，给出可复用的裁决规则。
3. **自审**：审计手册自身的证据链与自指偏差。
4. **加时态**：给结论打保质期、写复审触发器。

## 3. 被降级 / 重新定位的结论

| v2 结论 | v3 修正 | 依据 |
|---|---|---|
| **A1**（规则文件）是第一条 P0，隐含「写了就有效」 | 明确**不承诺任务正确率**。规则文件管约束、一致性、成本/延迟、协作契约与人类共识；任务失败先分「知识缺口 vs 能力缺口」 | arXiv:2607.27250（A，288 runs，correctness null，作者自列 8 条局限；purpose-built context 仍是开放问题） |
| **A3 / H1** 的「不可自动执行清单 + 审批流程」构成安全边界 | 提示层禁令**不是**安全边界；必须落到凭据、环境、爆炸半径层（dev/prod 隔离、备份异地、破坏性 API 延迟、token 单任务作用域、非人类身份） | 5 起公开事故（Replit / Kiro / Antigravity / Terraform destroy / PocketOS，B/C，当模式用） |
| **D1**（产出当待审 PR）是静态闸门 | 闸门会**随时间习惯化衰减**；补轮换、连续批准审计、个人批准率 + 下游缺陷轨迹 | arXiv:2606.22721（A，400 审查者 / 11,429 审查 / +14.5pp 批准率 / −22% 评论） |
| **C1**（外部信号优于自评） | 补「**信号本身会失信**」：红灯常亮则绿灯无意义；AI 审 AI 只发现 15–31% 人工标记问题 | Fowler 站白板周实验（A）、SWE-PRBench（B） |
| **B4**（小批量）有「经典定律」支撑 | 降级为「基于认知机制 + 多源方向一致 + 代价极低」的建议；400 行是软上限，**不是已证因果定律** | 400 行规则溯源（B）：2006 年 Cisco 单团队、厂商卖工具、70–90% 无出处、无证据证明大 PR 更易带 bug |
| **I3 六维记分卡**普适 | 加**规模分档**：小团队用 retro 简单 check-in 即可，复杂看板本身是成本 | Thoughtworks Radar Vol 34（A/B）：「简单机制如 retro check-in 可能更有力」 |
| **H 章 MCP** 只讲怎么安全用 | 补「先问是否必要」：`MCP by default` 被明确劝阻，理由是 abstraction tax；协议合规性 ≠ 架构必要性 | Thoughtworks macro trends（A） |
| 全书语气 = 规定性准则 | 重新定位为**一组带保质期的假设**：新方式建的系统「还没和生产一起生活过」 | Rachel Laycock / martinfowler.com（A）、结论反转记录 |

## 6. 仍诚实保留的边界

1. 未逐页通读 CAICT PDF；企业成效数字为企业自报（B 级）。
2. 事故案例多为第一人称叙述与媒体报道，Amazon 公开否认 AI 是主因；只作模式，不作判决。
3. HBR / Berkeley 研究有样本边界；不外推为「AI 一定让人更累」。
4. AGENTS.md 消融只覆盖 3 个 Python 仓库与两个模型快照；**「不承诺正确率」不等于「不必写规则文件」**。
5. 本轮**未执行任何编译 / 自检 / 测试，未改动任何源码**；只做联网检索、PDF 下载与文档写入。
6. 所有保质期标签本身也可能过时；L 章交付的是**复审规则**而非一张永久有效的表。

## 7. 一句话

v1 立规矩，v2 补盲点并改弱三处，v3 做的事是：**给每条规矩补上「什么时候它会失效」以及「怎么把它推翻」**。
