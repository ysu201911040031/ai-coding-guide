## 0 先说结论：六个人，两类课

这六位里 **五位教的是「造 Agent」，只有一位兼着教「用 Agent 的边界」**。而你需要的是**用 Agent 写 Qt 代码**——两者的交集比想象中小。所以这份清单只取「可迁移的认知」，明确剔掉框架与栈（LangGraph / CrewAI / AutoGen / Pydantic AI / RAG / 本地部署），理由很简单：那些东西半年一换，且和你的项目无关。

## 1 逐人：他真正在教什么

### 1.1 吴恩达 —— 架构比模型更能决定结果

- **四模式**：Reflection（自我批评并迭代）、Tool use、Planning、Multi-agent collaboration。
- **关键数字**（2024-03《The Batch》，多源一致）：GPT-3.5 单次 HumanEval **48.1%**；套进 agent 循环最高 **95.1%**；GPT-4 单次 **67.0%**。**套循环的提升大于换一代模型。**

**可迁移**：① 把钱和时间花在「循环」上（规则、测试、验证工具），而不是等更强的模型；② Reflection 只在配外部信号时有效——这与我们 C1 完全一致，等于给 C1 找到了产业侧背书。
**不可迁移**：课程里的平台实操、具体 prompt 技巧。
**落点**：C7（并补上他本人没提的反面：误差是乘的）。

### 1.2 Karpathy —— 把「AI 会失败」当成工程前提

三条我认为最值钱的话：

1. **「给我一个上千行的 diff 提交到我的仓库，这对我是没有用的。我仍然是瓶颈。」**——全网对「批量上限」最有力的同向证据，且出自最有资格说这话的人。
2. **自主性滑块**：自主度是设置项不是开关；好的产品让人按任务逐档调整；配套目标是让「生成—验证」循环尽可能快。
3. **锯齿状智能 + 顺行性遗忘**：模型在某些方面超人、在另一些方面像小孩，且**没有跨会话记忆**。

**可迁移**：① 滑块 → 直接做成 J6 的五档表；② 「顺行性遗忘」→ 规则文件的正确解释不是「持久化=有效」，而是**补偿一个具名缺陷**（改写了 A1 的依据）；③ 「让验证更快」→ 优先做**看得见**的 diff / 可视化，不是更长的说明。
**不可迁移**：Software 3.0 的宏大叙事——对单人项目没有操作价值。
**落点**：J6 新增；A1 依据改写；B4 的旁证。

### 1.3 李宏毅 —— 三个可直接改行为的实验结论

- **循环定义**：目标 → 观察 → 行动 → 改变环境 → 新观察。LLM 驱动的本质是「一直在做文字接龙」。
- **正面示例 > 负面禁止**：实验里只给负面例子最差、只给正面例子最好。「告诉他怎么做对，比告诉他别做错有效。」
- **脑内小剧场**：不可逆动作先在模拟里演一遍，再执行。
- **反面**：过度规划会导致**分析瘫痪**，思考与行动要平衡。

**可迁移**：① 改写我们规则文件的写法（A1 + 规则 §9）——我们通篇「禁止 / 不得」，这条是直接批评；② dry-run 先行的理论依据（B8）；③ 给规划设上限（B8）。
**不可迁移**：用强化学习对比讲 Agent 的铺垫、记忆模块的论文细节。
**落点**：A1 新增「写正例」；B8 新增；规则 §9 改写。

### 1.4 Cole Medin —— 上下文是被设计的工件

他给的是一套**可复制的工程流程**，五条技巧里四条我们没写：

1. **PRD-first**：一份 markdown 当北极星，拆成细粒度特性，让 agent 一次不做太多。
2. **模块化规则 + 渐进披露**：全局规则文件保持短小通用，细节放 reference 目录，全局只写「遇到 X 读 Y」——重上下文按需加载。
3. **命令化**：任何发过两次的 prompt 变成可复用命令。
4. **Context reset**：规划结束产出计划文档 → 清空对话 → 只带计划进入执行。
5. **System evolution**：不修 bug，修「允许这个 bug 存在的系统」。

旁证数据：Qodo 2025 调查 **76.4% 的开发者不信任未经审阅的 AI 代码**，主因是幻觉——而他认为幻觉主要是**上下文不足**，不是模型不行。（B 级）

**可迁移**：②③④⑤ 全部；「命令化」与花叔的「说过两次就写下来」**独立收敛**，可信度因此提高。
**不可迁移**：LangGraph / Pydantic AI / RAG 的具体栈。
**落点**：A1（模块化）、规则 §9（命令化）、B8（context reset）。

### 1.5 李沐 —— 读一手，不从二手结论起步（C 级，未独立核实）

方法特征：论文精读 + 从零复现。可迁移的只有一条，但很硬：**遇到「某框架/某模式很神」的说法，去看原始论文或原始仓库，而不是看解读。** 这条正是本手册全部证据分级（A/B/C）的同源理由。
反面教材也来自这一路：AutoGPT 式的全自主循环之所以失败，原因是**没有可靠的停止条件、也没有外部批评机制**——正好是 C3 与 C1 的反面案例。

### 1.6 Sam Witteveen —— 快速跟进框架，做原型验证（C 级，未独立核实）

特征：紧跟 LangChain / LlamaIndex / 多 Agent 新进展，端到端 demo。
可迁移：**原型验证优先于采购与重构**；以及一条警告——**别把流程焊死在某个框架上**，框架寿命通常短于流程寿命。
不可迁移：具体框架教程。

## 2 六个人交叉收敛的三条（这才是「融会贯通」）

| 收敛点 | 谁在说 | 我们原来的位置 |
|---|---|---|
| **上下文 > 提示词** | Ng 的 Tool use、Cole 的 context engineering、花叔的规则飞轮、李宏毅的记忆模块 | C 章已有，但没上升为「上下文是被设计的工件」 |
| **验证必须来自外部** | Ng 的 Reflection 配测试、Karpathy 的验证循环、李宏毅的工具回读、Anthropic 的 evaluator | C1 已有，这次拿到了产业侧背书 |
| **自主度要分级** | Karpathy 滑块、Anthropic「先用最简单的模式」、我们的 J3 爆炸半径 | 只有「按风险选模式」的模糊说法，现在有了档位 |

**三条合成一句**：*把上下文当作要设计的工件，把验证当作必须外挂的器官，把自主度当作可以拨的旋钮。*

## 3 与已有结论的冲突（一条，需要裁决）

**李宏毅：正面示例优于负面禁止 ↔ 本手册通篇「禁止 / 不得 / 不准」。**

**裁决**：不推翻，分两类处理。
- **安全硬边界**（人身/设备安全动作、越权访问、生产数据写操作、会破坏启动期依赖的链接方式）保留禁令形态——这类必须是一票否决，靠例子引导不够；
- **教育性、风格性、习惯性条目**改写为正例——这类禁令本来就不该存在，因为模型没见过「正确长什么样」，光说不对没用。

## 5 一句话

这六个人真正有价值的地方，不是他们各自的技术栈，而是**他们全都把「模型会失败」当作设计前提**——吴恩达用循环兜底，Karpathy 用滑块限权，李宏毅用模拟预演，Cole 用上下文前置。而我们手册的 J3（爆炸半径）与 J5（验证瓶颈），说的是同一件事在地下那一层的样子。
