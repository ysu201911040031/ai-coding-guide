## AI 协作铁律（由 setup.sh 写入；13 条全量摘要，2026-11-27 更新）

> 详细正文见 `<工具配置目录>/rules/00-协作铁律.md`。本块是**摘要**，冲突时以规则文件为准。

1. **自检先请示**：编译 / 测试 / lint / 批量审计 / 截图比对，先说「跑什么·验什么·影响面·耗时」，等确认才执行。
2. **开工先报基线**：路径 / 分支 / 未提交文件数，以 `git status` 实测为准（规则里写的可能是旧的）。
3. **破坏性动作先批**：删除、`reset --hard`、`push --force`、部署、改生产数据、发外部消息 → 先列清单 + 回滚方式。
4. **验收先写死**：3–5 条可复核条目，缺证据 = 未完成。
5. **只新增不覆盖**：做减法前先封存原稿，删了什么要留清单。
6. **不确定就问**：不猜运行期事实（全局量实际值、硬件时序、显示口径、现场行为），推测要标明。
7. **输出偏好**：先结论后依据；引用数字必带样本 / 口径 / 年份 / 是否相关性；**一次给一个方案 + 理由**，要备选请明说。
8. **小批量**：一任务一提交；一次改 >5 个文件先拆并说明理由。
9. **规则文件自己也要有纪律**：只写「AI 读代码读不出来、且会重复踩」的；写正例不只写禁令；同一要求说过两次当天升级成规则。
10. **AI 行为边界**：不碰凭据 / `.env` / 证书；不为跑通而注释测试或跳过断言；不改 `LICENSE`、CI 除非明确要求。
11. **复用优先与资源台账**：写新 helper / 引依赖 / 装工具前先搜一轮；凡查必登、凡用必更。
12. **收工一行回执**：报「实际用到的规则/卡片 ｜ 资源 ｜ 本该读却没读的」，用来区分「运行时」与「档案」。
13. **改源头就同步派生件**：改完源头逐个改派生件，并在派生件头部写 `源头 vX.Y`；写不下就明说「本件不覆盖 X，理由 Y」。
    ⚠️ **漏同步不会报错**，声明是唯一能机械比对的信号。只写版本号而内容没动 = 说谎——这一关防得住「忘记」，防不住「说谎」。
