# 可复制提示词（5 条，覆盖一天的工作节奏）

> 用法：直接整段复制，替换 `<>` 里的内容。不要"意思一下"，这五段的价值全在**不允许 AI 跳步**。

---

## P1 · 开工（新会话第一句）

```
开工前先做三件事，做完停下等我确认，不要写代码：

1. 报基线：pwd、git branch、git status --porcelain 的文件数，并逐条列出未提交文件
2. 指出本次任务可能触及的模块与边界（哪些层、哪些外部依赖），以及会不会碰不可逆动作（写库 / 发消息 / 操作硬件 / 部署）
3. 列出你打算先读的 3 个文件及理由

规则：基线以实测为准。不要引用规则文件里记录的旧基线。
```

**为什么**：90% 的回退成本来自"以为工作区是干净的"。

---

## P2 · 任务卡（真正动手前）

```
把这次改动写成任务卡，只填表不写代码：

- 目标：一句话
- 验收：3–5 条可复核条目，每条写清「怎么验」（命令 / 日志关键字 / 界面现象）
- 不做什么：列出这次明确不碰的东西（防顺手改）
- 触及文件：预判清单；超过 5 个就说明为什么不能拆
- 回滚：出问题怎么退回

我确认后再开工。
```

**为什么**：验收写不出来 = 任务还没想清。这条挡掉的是最贵的一类返工。

---

## P3 · 先要反对（脱回音室，单人必备）

```
先别给方案。用 200 字以内回答：

1. 这个想法最可能怎么失败？给 3 条，按可能性排序
2. 哪一条一旦成立，整个方案就不成立？
3. 要证伪这三条，我需要看什么证据（命令 / 日志 / 现象）？

回答完之后，再给方案。
```

**为什么**：AI 默认会同意你。没有这一步，你的判断就锚在"它说好"上，而不是锚在事实上。

---

## P4 · 隔夜冷读（第二天早上用）

```
你是明天早上第一次看这段 diff 的人，没有上下文，也不认识我。

只输出问题，不改代码：
- 哪一处改动，不看 commit message 就说不清意图？
- 哪一处引入的假设没有测试覆盖？
- 哪一处如果错了，会在什么现象上暴露？
- 按风险排序，最多 5 条，每条一句话。
```

**为什么**：单人没有审查者，这是唯一便宜的"陌生人视角"。

---

## P5 · 收尾交接（写进仓库，不写进聊天）

```
写五行交接，直接给出可粘贴进文件的 Markdown：

做到哪：
下一步：
坑：
别碰：
验收：

每行 ≤ 40 字，只写事实，不写感受。
```

**为什么**：下次会话读不到这次的聊天记录，只读得到仓库。这五行是单人版的"合并冲突"解药。

---

## 附：三条一次性提示（粘一次就够）

**A. 让它自评可信度**
```
对这个结论，给出你的置信度和理由。低于 0.7 的，明确说「这是推测，需要验证」。
```

**B. 换模型/换规则后回归**
```
读一下项目规则目录（项目级 `.qoder/rules/`；用户级 `~/.qoder-cn/rules/`）下的规则，列出你能复述的硬约束清单。凡是复述不出来的，说明它没写清楚，告诉我该改哪句。
```

**C. 月度自检（贴给 AI，让它反问你）**
```
按下面 5 条依次问我，每条等我回答后再问下一条，不要一次全问：
1. 这个月有没有一次我否掉了你的方案？
2. 有没有一次我亲手验过你说对的东西？
3. 三个月前写的代码，我还讲得清它怎么坏吗？
4. 最近一次从零手写核心逻辑是什么时候？
5. 速查卡被打开过几次？0 次就该归档了。
```
