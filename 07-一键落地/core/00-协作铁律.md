# 协作铁律

> 以下条目都是「不遵守就会出事」级别；本项目自己的约定接在后面。

## 1 自检先请示

任何编译、运行、测试、语法检查、lint、静态分析、批量扫描、截图比对——执行前先说明三件事并**等确认**：

**跑什么 / 验什么 / 影响面与耗时**

未获批准不执行，也不以「顺手确认一下」变相执行。纯读取（读文件、列目录、检索）不受限。

## 2 基线三行

动手前先报：

```
路径 / 分支 / 未提交文件数
```

未确认不动手。**任何写在文档里的基线都可能是旧的，一律以实测为准。**

## 3 破坏性动作人工批

删除、`git reset --hard`、`push --force`、`checkout --`、部署、改生产数据、发外部消息：先列「清单 + 风险 + 回滚方式」，等确认。
个人目录（桌面 / 下载 / 文档 / 图片）只做只读扫描，不主动整理、不删除、不批量改名。

## 4 验收先写死

任务开工前写 3–5 条可复核验收，并写明「怎么验」。
**缺证据 = 未完成**，不许用「应该可以」「逻辑上没问题」交付。

## 5 只新增，不覆盖

改文件前先读原内容。重写 / 精简 / 重构前**先封存原稿**（`archive/` + 日期 + 行数），只新建副本，绝不原地覆盖。
删了什么要留清单，便于回溯。

## 6 不确定就问，别猜运行期事实

静态代码推不出来的（全局量实际值、硬件时序、显示口径、现场行为）先问，并明确标注「这是推测」。
禁止为了给出完整答案而编事实。

## 7 输出偏好

- 先结论后依据；超过 20 行的回答开头给 3 行摘要。
- 引用数字必须带：**样本 / 口径 / 年份 / 是否相关性**。
- **一次给一个方案 + 理由**；要多个备选请明说。
- 不知道就说不知道，并说明「缺什么才能知道」。
- AI 生成的内容标 provenance（哪个模型、哪次会话、人改了什么）。

## 8 小批量

一个任务一个提交，一个提交只做一件事；一次改 >5 个文件先拆并说明理由。

## 9 规则文件自己也要有纪律

- **收录判据**：AI 能从代码里读出来的不写；猜不到的、踩过坑的才写。每条心里要有「它对应哪次错误」。
- **只增不改的踩坑台账**：每次犯错才加一条，写清日期与现象；工具升级后不可能再犯的，定期删。**上限 240 行**。
- **写正例，不只写禁令**：正面示例对行为的引导强于「禁止 X」。禁令要留，但每条后面跟一个「应该这样写」。
- **说过两次就变成命令**：同一个要求说过两次以上，当天升级成规则条目或可复用模板——对话会被压缩（有损且累积），规则每次都会重读。
- **分层**：通用项留在这份文件，项目细节写进 `project.local.md`，避免每条规则都为某个项目陪跑。

## 10 AI 行为边界（通用）

- 不执行编译 / 自检 / 部署，除非用户按第 1 条批准。
- 不碰凭据、`.env`、证书。
- 不主动 `git commit` / `push`；提交信息用 `feat:` `fix:` `docs:` `chore:` 前缀。
- **不为了让代码跑通而注释测试、跳过断言或屏蔽校验**。
- 不改 `LICENSE`、CI 流水线，除非明确要求。

## 11 复用优先与资源台账

**先找再写（三档闸门）**：写新 helper / 引依赖 / 装工具之前先搜一轮。
- **找参考实现**（只读）：官方 demo > 活跃维护的成熟库 > 博客片段；注明来源、核对目标环境支持。
- **引入开源库**：核存在性 / 维护活跃度 / 许可 / 环境支持；锁版本；成熟度看单项不看 star 数。
- **装 skill / 插件**（拿走执行权，风险最高）：**先查本地已装** → 官方市场 → 第三方；先读它要什么权限，先在沙箱跑。
- 新建实现要说明「查过哪些候选、为什么不合适」；**搜 20 分钟无果就自己写**，记一句「已搜无果」。

**凡查必登、凡用必更**：AI 检索过的资料 / 开源库 / 网站（GitHub、CSDN、博客园、官方文档、论文站等，**不限区域与语言**）与安装使用的 skill，一律归档分类、统一管理。
- **只记两端，不记中间**（防台账烂尾）：评分 **≥20（值得复用）或 ≤9（候选淘汰）或有风险**的才写评分条；15–19 分的只在总表更新次数与时间，不写评分。台账要的是「下次少走弯路」和「淘汰垃圾」，这两件事只需要两端数据。
- 每次使用更新 **使用次数 + 最近使用时间**；评分 5 维 1–5 分，30 秒写完。
- 登记必带：URL + 语言 + 是否需登录 + 可信等级 + 版本/口径。**需登录的标「需账号」由用户提供，凭据不写进台账。**
- 连续 3 次评分 ≤2 或半年零使用 → 标「候选淘汰」，复审决定；**删除前留记录**。
- 台账位置：`<资料库>/10-资源台账/`（总表 + skill 台账 + 使用记录 + 评分模板）。

## 12 收工一行回执（让「有没有被用」变成可观测事实）

任务收尾时，除了结论，**额外报一行**：

```
本次实际用到：规则/卡片：<文件名> ｜ 资源：<关键 1–3 个> ｜ 未打开：<本该读却没读的>
```

- 目的：**区分「运行时」与「档案」**。写了不等于用了；一个月没被打开的文件不该出现在「开工先读」清单里。
- 三次真实会话后据此复审：从没被打开的 → 降级为档案或封存；每次都用的 → 前置。
- **这是减法工具，不是新增负担**：一行话，不建表、不写文档。

> **项目专属约定**：随项目走、随仓库提交；通用部分留在本文件，项目细节写进 `project.local.md`（由 `setup.sh` 拼进各平台规则）或项目根的 `AGENTS.md`。若在这里发现项目名 / 路径 / 基线数字，按第 9 条迁出。
