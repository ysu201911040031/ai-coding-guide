# 开工对齐

## Overview

目标不是写代码，是**在动手前把"要做什么"变成双方都认得的任务卡**。产出是一张卡，不是一堵 diff。

## When to Use

- 新项目 / 新功能 / 新模块 / 新依赖 / 跨模块重构
- 用户说"开工""先规划""要不要找现成的"

**不触发**：bug 修复（走 `diagnose`）、单行修改、纯问答、已有任务卡的任务。

## Process

1. **先跑开工卡**：项目里有 `.ai/preflight.py` 就跑一次，报基线 / 环境 / 复用提醒。没有就手报三行（路径 / 分支 / 未提交数）。
2. **先读再问**：读 README、`AGENTS.md`、相关代码与既有任务卡。**能读到的不要问**。
3. **五问**（简版 grilling，一次问完，不要挤牙膏）：
   1. 目标是什么？**非目标**是什么？
   2. 3–5 条验收，每条怎么验？
   3. 影响面：允许改哪些文件/层？哪些绝对不碰？
   4. 最可能怎么失败？（至少说一条）
   5. 要不要先搜现成实现？默认搜 10 分钟，无果再写。
4. **出任务卡**（就这 8 行，不要扩写）：

```
意图：
非目标：
边界（可改 / 禁碰）：
基线（路径 / 分支 / 未提交）：
计划（3–5 步，每步一个产物）：
验收（3–5 条，可复核）：
验证方式（外部信号）：
停止条件（max 轮数 / 转人工阈值）：
```

5. **等确认**。用户没说"开始"之前，不写文件、不建目录、不装依赖。

## Rationalizations

| 借口 | 反驳 |
|---|---|
| "需求很清楚，不用问" | 清楚的是你的理解，不是双方共识。先复述一遍，让对方改。 |
| "先做一版再对齐" | 返工成本 > 五问成本；只有一次性原型可跳过，并标"不可上线"。 |
| "搜索太慢，直接写" | 默认 10 分钟止损；写之前先记一句"已搜无果"（D8）。 |
| "任务卡太形式化" | 卡的作用是让验收可复核；没有卡，收尾时只能靠记忆吵架。 |

## Red Flags

- 任务卡里出现"优化一下""完善""按最佳实践"这类无法验收的词
- 一次计划改 >5 个文件
- 目标是"先跑起来"，但没写"跑起来之后怎么算对"

## Verification

- 任务卡 8 行齐全，验收 3–5 条且每条有验证方式
- 「非目标」至少一条
- 用户明确说"开始"之后才产生第一个文件改动

## 与规则的关系

A2（基线）、B8（拆到可验证）、C2（验收先写死）、D8（复用优先）、F5（自检先请示）。
本 skill 只负责触发流程，不复述条款；冲突时以 `core/00-协作铁律.md` 为准。
