# 收尾

## Overview

收尾不是"写完了"，是**每条验收都有证据，下一个人能接着干**。聊天记录不算交接，仓库才算。

## When to Use

- 一个任务/会话结束前
- 提交前、交接前
- 用户说"收尾""总结一下""提交吧"

**不触发**：任务中途的进度汇报。

## Process

1. **对账**：打开任务卡，逐条勾验收。没证据的写"未验证"，不许用"应该可以"。
2. **跑最小验证集**（先请示）：相关测试 / 构建 / lint / 运行日志，贴输出摘要，不贴整屏。
3. **写交接**（进仓库，不进聊天）：

```
## 交接 YYYY-MM-DD
做到哪：
下一步：
坑：
别碰：
验收：
```

4. **两行附加**：
   - `provenance：模型 / 会话 / 人改了什么`
   - `理解力债：有没有一段我讲不出「它怎么坏」？`——有就记一次。
5. **清理**：删自己产生的临时文件与调试输出；不删既有死代码（只在交接里提一句）。
6. **提交边界**：一任务一提交；列出改了哪些文件、为什么、如何验证。

## Rationalizations

| 借口 | 反驳 |
|---|---|
| "测试跑过了，不用再跑" | 收尾跑的是**最小验证集**；上一次跑可能是在中途改动之前。 |
| "交接写在聊天里就行" | 下次会话读不到聊天，只读得到仓库。 |
| "先提交，验收回头补" | 没验收的提交把回滚成本预支给明天。 |
| "这点小事不用写交接" | 小事也会隔夜；五行比回忆便宜。 |

## Red Flags

- 验收条目出现"基本完成""应该没问题"
- 工作区有未提交文件但说不清是什么
- 交接里没有"别碰"和"下一步"
- 这次改动没有对应任何验收条目

## Verification

- 每条验收都有证据或明确标"未验证"
- 交接五行在仓库文件里，不在聊天里
- `git status` 干净，或未提交项逐条列出并有归属
- 提交信息能回答：改了什么、为什么、如何验证
