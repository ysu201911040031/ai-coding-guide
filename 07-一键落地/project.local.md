# 项目约定（通用基线 · 待填）

> 这份是**开箱能用**的通用版：`硬约束 / 不许做 / 验收` 三节对几乎所有项目都成立；
> `命令 / 分层 / 已知坑` 三节需要你按项目替换。不确定的先留着，比编一个错的强。

## 项目

- 一句话：`<这个仓库做什么、给谁用>`
- 主分支：`main`｜分支前缀：`feat/` `fix/` `chore/`
- 产物目录：`build/` `dist/`（**不手改**）

## 开工卡（每次会话）

- 会话开始运行 `.ai/preflight.py`，报三行：基线 / 环境 / 复用提醒；**环境每会话只报一次**。
- 环境漂移或超过 30 天未核对 → 先确认再动手；变更写 `.ai/env-log.md`（日期 / 字段 / 旧值 / 新值 / 证据）。
- 新功能 / 新模块 / 新依赖 → 先问「要不要搜现成实现」（默认 10 分钟，无果再写）；bug 修复不问。
- 复用无果 → 查项目提示词库索引，不要直接去 GitHub 现搜。

## 术语表（业务词）

- 位置 `docs/ai/术语表.md`；`AGENTS.md` 只留一行指针，不复述内容。
- 只在「AI 因这个词理解错一次」后加一条；上限 30 条 / 一屏。
- 每条四列：术语 / 一句话定义（含边界）/ 容易混淆 / 代码入口（可选）。
- 代码改名或语义变更时，同一次改动里改表；不许两种写法并存。

## 硬约束（违反会出事）

- 禁止手改**生成物**（`dist/`、`build/`、`*.min.js`、自动生成代码）→ 改源文件后重新生成。
- 禁止提交**凭据**：`.env`、密钥、证书、token、连接串 → 走环境变量或本地未跟踪文件。
- 禁止未经确认安装**新依赖** → 先说明用途、体积、维护状态，等批准。
- 禁止为「让代码跑通」而**注释测试 / 跳过断言 / 吞异常** → 修实现或修测试。
- 禁止 `git reset --hard`、`push --force`、删除文件 → 需要时先列清单 + 回滚方案。
- 禁止直接在**生产环境**跑脚本 → 先在本地/预发 dry-run，要求幂等 + 可回滚。
- 数据变更（迁移 / 批量更新 / 删除）必须：**可回滚 + 幂等 + 先备份 + 小批灰度**。
- 涉及对外动作（发消息、发邮件、调付费 API、部署）→ 先说明影响面，等确认。

- 外部依赖只能从 `<唯一入口>` 引入。
- 跨模块调用走 `<接口 / 事件>`，不直接引用对方内部实现。

## 不许 AI 做的事

- 不执行编译 / 测试 / 安装 / 部署 / 批量脚本（**先问，批准后跑**）。
- 不读、不改凭据、`.env`、证书、CI 密钥。
- 不主动 `git commit` / `push`，除非明确要求；提交信息用 `feat:` `fix:` `docs:` 前缀。
- 不改 `LICENSE`、`CODEOWNERS`、发布流水线，除非明确要求。
- 不引入遥测、外发数据、第三方上报。

## 验收

- 开工前写 3–5 条可复核验收，每条写明「怎么验」。
- **缺证据 = 未完成**；「应该可以」「逻辑上没问题」不算。
- 一次只交付一个可独立验收的单位；超过 5 个文件先拆。
